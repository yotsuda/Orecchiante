# Orecchiante → Lily#: ドラムを打ち込み風に書く `steps`（依頼 24）

2026-11-26、Orecchiante のセッションから。オーナーと話して出した依頼（オーナー「ドラム譜は、もっと簡単に書ける表記方法が
あると良いかもしれない」→ Orecchiante の提案 2 → 「用意して」）。入れるかどうか、どう入れるかは Lily# とオーナーの判断。

## 1. なぜ

ドラムを今の書き方（音の長さを並べる）で書くと、3 つの手間がある。

- **小節を長さで埋める計算**: `r8 bd16 r16 r4 bd8. r16` のように、休符と音の長さの合計を毎回 1 小節ちょうどにする。
  シンコペーションが多いと誤りやすく、1/16 足りないと長さのエラーになる。
- **位置で考えたことを長さに直す手間**: ドラムは「キックは 1 拍目と 3 拍目の裏、スネアは 2・4」と**位置**で考える。
  それを休符と長さの列に直している。
- **行どうしの揃え**: ハイハット・スネア・キックが同じ時刻に打つかは、各行の長さを頭から足さないと分からない。
  1 打だけ直すと前後の休符も書き直しになる。

手間がかかるのは、人がテキストで打ち込むとき、AI（Copilot のチャットで作曲するとき、Orecchiante のセッション）が書くとき、
Orecchiante が録音から書き出すとき。Orecchiante 0.14.0 は曲の型を phrase で 1 回だけ書き、小節は型の名前と `%` で並べる形に
した（依頼 23 の便り §1）。それでも、型の中身は長さの列のままになる。

## 2. 提案する形

```
part kit { clef percussion }
phrase beatA {
  steps {
    hh "x.x. x.x. x.x. x.x."
    sn ".... x... .... x..."
    bd "x... ..x. x.x. ...."
  }
}
section A {
  kit { beatA | % | % | steps { hh "xxxx xxxx xxxx x.o." sn ".... x... ..gg x.xx" bd "x... ..x. x... ...." } | }
}
```

- **1 文字が 1 つの刻み、空白で区切ったかたまりが 1 拍。** かたまりの文字数がその拍の細かさを決める: 4 文字＝16 分、
  2 文字＝8 分、3 文字＝8 分の 3 連（シャッフル）、6 文字＝16 分の 3 連、1 文字＝4 分。拍は拍子の拍
  （4/4 なら 4 分、6/8 なら付点 4 分で 1 小節 2 かたまり、3 文字で 8 分）。1 つの行の中で拍ごとに細かさが変わってよい
  （`"x.x. x.x. xxx x..."`＝3 拍目だけ 3 連）。行ごとに違ってもよい（`bd "x. .x x. .."`＝キックは 8 分で考える）。
- **拍の区切りの空白は必須にしてほしい。** 区切りのない 16 文字（`x.x.x.x.x.x.x.x.`）は、人にも AI にも数え間違えやすい
  （AI は文字をまとめて読むので、15 文字や 17 文字を書いてしまうことがある）。4 文字のかたまりが 4 つなら、拍の位置で
  考えたまま書ける。
- **行の名前は今の太鼓の名前**（`hh` `hho` `hhp` `sn` `ss` `bd` `tomh` … `cymc` `cymr` …）。手と足の振り分け（符尾の上下）は
  今の `drums { }` の決まりと同じ。
- **記号**（案。足し方は Lily# の判断）:

  | 記号 | 意味 |
  |---|---|
  | `.` | 打たない |
  | `x` | 打つ |
  | `X` | アクセント（`@accent` と同じ） |
  | `g` | ゴースト（括弧つきの符頭、弱く鳴らす） |
  | `o` | ハイハットを開く（`hh` の行で。`hho` と同じ） |
  | `f` | フラム（`acciaccatura { sn16 } sn` と同じ） |

- **音の長さ**: 打った音は同じ行の次の打撃まで、または拍の終わりまで（ドラムは伸ばさないので、刷るときの見た目だけの話）。
  休符のまとめ方・連桁は今の `drums { }` と同じ決まりで刷る。
- **何小節でも書ける**: 文字列の中の `|` で小節を区切る（`hh "x.x. x.x. x.x. x.x. | x.x. x.x. xxxx xxxx"`）。全部の行で
  小節の数が同じであること。`steps { }` の後の `|`・`%`・phrase への入れ方は今の `drums { }` と同じ。
- **書き出しは全部、今の音符と同じ**（MIDI・wav・MusicXML・LilyPond）。中身は今の太鼓の音符と同じなので、音と紙は
  今の仕組みに乗るはず。

## 3. エラー（AI と人が直せる言い方で）

- かたまりの数が拍子と合わない: 「`sn` の行の 2 小節目: 拍が 3 つ（4/4 は 4 つ）」。
- 知らない記号: 「`hh` の行の 1 拍目の 3 文字目 `y`: 使える記号は `. x X g o f`」。
- 行によって小節の数が違う: 「`bd` は 2 小節、ほかは 1 小節」。
- `o` を `hh` 以外の行に書いた、など意味の無い組み合わせは警告。

行と小節と拍を名指しすれば、数え間違えてもすぐ直せる。

## 4. あると便利なもの（あれば）

- エディタで `drums { }`（長さの列）と `steps { }` を行き来する変換（Ctrl+. など）。今の楽譜を打ち込み風に直して確かめられる。
- 刻みの細かさを超える音（`steps` で書けない 32 分など）は、変換で `drums { }` のまま残す。

## 5. Orecchiante の側

`steps` が入ったら、ドラムの段の型を `steps` で書く（`src/Orecchiante/Kit.cs`・`tools/drums.py`）。今は 16 分の格子で読んで
いるので、1 拍 4 文字で書けば足りる。隣のファイルの各小節の `drums` も同じ表記にすると、報告（依頼 23）の比べる元も読みやすい。
